# AnimeKai v2.0.4 — Server 1 / Server 2 race

CloudAnime 1.8.40. Apply this ZIP at the repository root. Includes manifest.json, providers/animekai.js, this note and scripts/test-animekai-v204.cjs. No extra enclosing folder, workflows or deletions. Works on the original uploaded archive or v2.0.3; no earlier patch is required.

After one ARM mapping and one website episode page, race eligible page-listed MegaPlay (Server 1) and direct MegaVid (Server 2). Keep the first successfully extracted, verified master HLS. A fast HTML/error/invalid playlist response cannot win. Abort the losing task and prevent further requests from it. Server 3's /aniwave/ route is excluded completely, per the user's observed wrong-episode playback.

The episode guard remains: exact active episode, published entry, Sub availability and exact mapped MAL/episode player route. No air-date checks, guessed episode offsets or additional metadata services. ARM's anime-planet slug is only a page lookup hint; missing/unusable hints return no results. A page/server can still mislabel media content; no video-frame identity analysis is performed.

MegaPlay loads its listed player, reads the actual player data-id and calls /stream/getSources. Its published AES-CBC source payload is decoded using the existing crypto-js runtime module already used elsewhere in this repository. The manifest declares this runtime dependency. MegaVid uses /source?noax=1 and retries HTML, HTTP 5xx or request timeout once within the shared 24-second deadline. Identity conflicts, missing episodes and invalid playlists are not blindly retried. HTML responses now generate a useful stage error rather than a bare JSON token error. No health/CDN probing is added.

Both candidates validate HLS and reject explicitly mixed/unknown audio renditions as before. English, Malay and Indonesian subtitle sidecars are retained; thumbnail VTT is excluded. Successful stream serverName identifies the winning host. Race adds concurrent requests versus a single host, rather than waiting for one host to fail first. Headers preserve each host's Origin/Referer.

Validation: all 15 providers pass syntax/manifest validation; 13 controlled regression cases pass, covering both race winners, cancellation during source and HLS fetches, HTML retry, both-server failure, excluded Server 3, unavailable/redirected/wrong episode/season, source identity conflict, mixed audio and subtitle filtering. Recorded real website/player/encrypted MegaPlay response decodes to its expected URL (HLS mocked). A hybrid test using recorded website metadata and live server requests returned one verified MegaVid HLS with three allowed subtitle tracks; MegaPlay was cancelled. A full live S2E2 run also succeeded: MegaVid won, three subtitle languages (en/id/ms), seven HTTP calls, approximately 19.9 seconds. This verifies source discovery, not full video playback or all episodes. MegaPlay's decoded CDN URL returned an unavailable HTML page from this environment during a separate probe; no unverified video URL is returned in that case.

Run `npm ci --ignore-scripts`, `node scripts/validate.mjs`, `node scripts/test-animekai-v204.cjs`. Older version-specific tests describe their older implementation. All other provider files and manifest entries remain unchanged.
